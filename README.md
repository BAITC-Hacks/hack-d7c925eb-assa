# Career Quest

Карьерный помощник на синтетическом наборе: 200 сотрудников, каталог обучения, оценки навыков и история участия. Сотрудник видит подтверждённый уровень, требования цели, ожидаемый эффект обучения и следующий доступный шаг. HR получает дефициты, причины отсутствия рекомендаций и участие своего отдела.

Основной разговор проходит в **AI-чате**: вопрос → серверные инструменты → ответ и интерактивные карточки → уточнение или подтверждённое действие. Слева остаются карта, маршрут, история и настройки профиля. На телефоне навигация открывается кнопкой «Меню».

## Быстрый старт — Windows

Нужны Python 3.11+ и Node.js 20.9+ с npm в PATH, доступ к реестрам pip/npm при первой установке. Распакуйте проект в доступную для записи папку и откройте PowerShell в ней:

```powershell
.\run.ps1
```

Если локальная политика PowerShell блокирует файл, можно разрешить выполнение только для этого запуска:

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

Скрипт создаёт `.venv`, устанавливает Python-зависимости и frontend через `npm ci`, создаёт SQLite **только при отсутствии файла**, запускает оба сервиса и проверяет готовность. Откройте [приложение](http://localhost:3000), нажмите «AI-чат», отправьте «Чего не хватает до следующего грейда?». Затем «Что делать дальше?» и «А второй вариант?».

При повторном запуске прогресс сохраняется. Ctrl+C завершает процессы этого запуска и их дочерние процессы. Уже работающая пара сервисов определяется без повторного запуска. Если занят один порт или на порту другое приложение, скрипт сообщает об этом; чужие процессы не завершает.

```powershell
.\run.ps1 -PrepareOnly  # только зависимости и база
.\run.ps1 -SmokeTest    # запуск, проверка HTTP и остановка
```

## Локальный помощник и модель

Без ключа работает явно подписанный локальный помощник. Он понимает команды карты/уровня/маршрута, время («У меня час»), формат («Без очных встреч»), снятие ограничений, сравнение и объяснение выбранной активности, учебные примеры, три HR-среза. Неизвестный или неоднозначный запрос получает уточнение. Это ограниченный обработчик команд, а не универсальная языковая модель.

Для AI-режима скопируйте `backend/.env.example` в `backend/.env` и настройте сервер. Ключи не добавляйте в Git или переменные `NEXT_PUBLIC_*`.

| Параметр | Назначение |
|---|---|
| `CQ_MODE` | `demo` только на loopback или `private` с кодами доступа |
| `CQ_ALLOW_EXTERNAL_AI` | `true` только когда разрешена передача контекста выбранному провайдеру |
| `OPENAI_API_KEY` | Серверный ключ API |
| `OPENAI_MODEL` | Доступная вашему аккаунту модель с Responses/function calling; значение шаблона — `gpt-4.1-mini` |
| `CQ_EMPLOYEE_ACCESS_CODE` | Отдельный случайный код сотрудника длиной от 16 символов |
| `CQ_HR_ACCESS_CODE` | Другой случайный код HR длиной от 16 символов |
| `CQ_EMPLOYEE_ID` | Привязанный на сервере сотрудник, например `E0001` |
| `CQ_HR_DEPARTMENT` | Точное название разрешённого отдела |
| `CQ_CORS_ORIGINS` | Разрешённые адреса frontend через запятую, без пробелов |

Endpoint модели фиксирован: `https://api.openai.com/v1/responses`. Произвольный URL из чата или браузера не принимается. Процессные переменные имеют приоритет над `.env`. Сначала читается `backend/.env`, затем корневой `.env`; для совместимости старый ключ из `frontend/.env` читается только backend. Для новых установок используйте исключительно `backend/.env`.

Перезапустите сервисы после настройки. Надпись «AI-агент с инструментами» означает, что серверная конфигурация включена; успешное соединение подтверждает только ответ с отметкой «AI + проверенные данные». Неверный ключ, таймаут, неверные аргументы или незавершённый цикл дают явно обозначенный локальный ответ. Тело ошибки провайдера и ключ не возвращаются клиенту.

## Как работает агент

```text
Вопрос + контекст текущей серверной сессии
  → модель выбирает инструмент (локально — обработчик команд)
  → сервер проверяет роль, аргументы, доступ и ограничения
  → SQLite + Recommendation Engine рассчитывают факты
  → проверенный ответ + тип готового React-компонента
  → карта, маршрут, сравнение или HR-сводка внутри диалога
```

Инструменты: `get_my_context`, `find_development_options`, `simulate_route`, `explain_options`, `get_skill_guide`, `get_team_gaps`, `get_coverage_gaps`, `get_team_participation`, `ask_clarification`, `present_artifact`. Модель выбирает действия, сервер формирует числовые утверждения и итоговые фактические объяснения. Произвольный HTML, JS и SQL модели не исполняются.

Пример: «У меня час, только онлайн» → `get_my_context` → `find_development_options(max_minutes=60,event_format=online)` → поиск доступных online/self-paced событий текущего грейда с полезным приростом → `simulate_route` → `present_artifact(next_step)`. Если вариантов нет, ответ показывает причины фильтрации. «Сними ограничение по времени» сохраняет формат. «А второй?» использует последний список; без списка задаётся уточнение.

Контекст содержит до 12 последних сообщений/кратких описаний результата, выбранные ID активностей и ограничения. `conversation_id` принадлежит одной сессии. Факты перечитываются перед каждым ответом. Имена и сырая персональная история не входят в результаты инструментов для провайдера; HR-списки с именами остаются на сервере и в разрешённом интерфейсе. Сам пользователь может ввести личные данные в вопрос — учитывайте это при включении внешнего режима.

Лимиты: сообщение до 2000 символов, 20 запросов/минуту на сессию, один запрос одновременно, до трёх раундов модели и шести инструментов, 9 секунд на модельный цикл с последующим локальным ответом. Клиент отменяет ожидание через 15 секунд. Желаемый общий SLA 10 секунд проверяется отдельно на доступной модели и сети.

«Разобрать с агентом» передаёт структурированный `event_id`. Объяснение альтернативы не зависит от слов в тексте кнопки. «Сравнить варианты» показывает факторы двух активностей. Старые карточки сохраняются с меткой предыдущего результата и отключёнными изменяющими действиями. Кнопка завершения открывает подтверждение; сервер заново проверяет доступность. Фраза «я это знаю» не меняет навыки.

## Уровни, история, доступность

- Подтверждённые навыки и грейд берутся из профиля. Грейд автоматически не повышается.
- Ожидаемый уровень учитывает **все завершённые записи строго после `last_review_date`**, независимо от происхождения. Запись в день оценки или раньше считается уже включённой в review.
- Для каждого события в хронологическом порядке: `new = max(old, min(5, max_level, old + gain))`. Высокий уровень не понижается, прирост ограничен конкретным событием.
- Карта показывает полный набор требований цели и дополнительные текущие навыки. Готовность — число выполненных требований / число всех требований, а не процент закрытия списка дефицитов. При отсутствии требований показывается отсутствие данных.
- Цель можно явно сохранить из обычного раздела. Без цели используются требования текущей роли с соответствующей подписью.
- Допуск к событию определяется **текущими подтверждёнными ролью и грейдом**, а также подтверждёнными prerequisites. Цель определяет полезность обучения, но не открывает доступ. Ожидаемый прирост не заменяет оценку prerequisite.
- Обычная активность завершается один раз. Для `EV_036` единица участия — дата сессии; повтор того же `participation_id` не начисляет прирост, следующая доступная сессия допускает новое участие.
- Даты и доступность используют синтетический срез **2026-10-01**. Демо позволяет отмечать выбранные сессии каталога как пройденные для показа пересчёта; это не календарь фактического посещения.
- Recommendation Score учитывает цель/критичность, полезное сокращение разрыва, историю, длительность и эффективность времени. Это оценка соответствия, не вероятность повышения. История без записей отличается от записей с пропусками.

## Доступ и сохранение

Demo явно обозначено и доступно только с локального компьютера. Переключатель синтетических профилей/ролей не является авторизацией. В `private` код сотрудника привязан к `CQ_EMPLOYEE_ID`; переданный клиентом другой ID не изменяет привязку. HR-код отдельный, область ограничена отделом. Backend проверяет API, инструменты и изменения независимо от текста «я HR».

Сессии хранятся в памяти backend до 8 часов, после рестарта требуется вход. Токен в sessionStorage текущей вкладки позволяет восстановить сессию после reload с проверкой сервером; выбранный раздел хранится отдельно для профиля/роли. Диалог и черновик сохраняются при закрытии/открытии чата, но не переживают reload. Смена сессии очищает визуальный диалог. Это пилот с двумя заранее настроенными доступами, без регистрации и SSO.

SQLite: `backend/data/career_quest.db`. Перед переносом или сбросом остановите приложение и сделайте копию:

```powershell
Copy-Item backend/data/career_quest.db backend/data/career_quest.backup.db
```

Добавочный импорт папки с `employees.json` и/или `activity_history.csv` в исходной схеме:

```powershell
.\.venv\Scripts\python.exe backend/scripts/import_dataset.py --append C:\path\to\new-data
```

Импорт валидирует поля, уровни, диапазоны, даты, ссылки на события/навыки/роли и конфликты ID, выполняется транзакционно. При ошибке выдаёт строки ошибок и откатывает всю операцию. Повтор одинакового файла не создаёт дубли. Существующие оценки/цели и прогресс не перезаписываются; изменение уже импортированного профиля отклоняется. Каталог новых событий/навыков этим режимом не расширяется.

**Разрушительный сброс всех данных и прогресса** выполняется только явно:

```powershell
.\.venv\Scripts\python.exe backend/scripts/import_dataset.py --reset
```

Без `--reset` импортёр отказывается пересоздавать существующую базу. Повреждённая база останавливает запуск и требует восстановления из копии.

## Два сценария демонстрации

Сотрудник `E0001`: откройте AI-чат → «Покажи карту навыков» (App Security подтверждён 0, ожидается 1 благодаря EV_011 от 25 сентября после review 11 сентября) → «Что делать дальше?» (до трёх допустимых вариантов) → «А второй вариант?» (объяснение именно альтернативы) → «Только онлайн» (новый подбор) → отметьте доступное событие и подтвердите (обновлённая карта в диалоге) → reload (прогресс сохранён).

HR в demo или с HR-кодом: «Какие навыки проседают?» → «У кого нет следующего шага?» → «Какое участие по активностям?». Данные относятся к разрешённому отделу; причины отсутствия шага показывают фильтры каталога. Сотруднику эти три запроса в private недоступны. Низкое участие не трактуется как низкая результативность или намерение уволиться.

## Телефон и голос

Для доступа с телефона нужен `private` режим, доверенная локальная сеть, отдельные коды и разрешённый адрес frontend в `CQ_CORS_ORIGINS`. Не публикуйте demo-сервер. В `frontend/.env.local` задайте `NEXT_PUBLIC_API_URL=http://<LAN-IP-компьютера>:8000/api/v1`, на сервере `CQ_CORS_ORIGINS=http://<LAN-IP-компьютера>:3000`. После этого запускайте вручную:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000
# Другой терминал:
cd frontend
npm run dev -- --hostname 0.0.0.0 --port 3000
```

Ограничьте доступ в firewall доверенной сетью/устройством. Для передачи токенов вне изолированного тестового окружения нужен HTTPS; используйте свой доверенный reverse proxy и соответствующие HTTPS URL/CORS. Настройка firewall и сертификатов скриптом не выполняется.

Кнопка «Голос» использует поддерживаемое браузером распознавание: явное подтверждение обработки браузерным сервисом → разрешение микрофона → запись/стоп → редактируемая расшифровка. Автоотправки и непрерывного прослушивания нет. При отказе/неподдерживаемом API остаётся текст. На телефоне распознаванию может требоваться HTTPS; совместимость и внешний контур зависят от браузера и должны быть проверены перед применением.

## Ошибки и проверки

| Симптом | Действие |
|---|---|
| Пакеты не устанавливаются | Проверьте доступ к pip/npm и настройки корпоративного proxy; запустите `-PrepareOnly` повторно |
| Порт занят | Освободите 3000/8000 или используйте уже запущенную пару; скрипт не убивает чужие процессы |
| Backend недоступен | Смотрите `backend/server-error.log`, проверьте `.venv`, БД и URL API |
| Frontend не запускается | Смотрите `frontend/server-error.log`, версию Node и результат `npm ci` |
| Неверный ключ/модель не отвечает | Проверьте серверный `.env`, доступ модели и разрешение внешней передачи, перезапустите; доступен локальный ответ |
| Нет рекомендаций | Прочтите причины: время, формат, текущий грейд, prerequisites, завершение, даты или отсутствие полезного прироста |
| Сессия истекла | Войдите снова; прогресс в SQLite остаётся |
| Ошибка запроса в чате | Нажмите «Повторить»; исходный вопрос остаётся в ленте |

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
cd frontend
npx tsc --noEmit
npm run build
```

Результаты текущей проверки и оставшиеся условия приёмки: [audit/IMPLEMENTATION.md](audit/IMPLEMENTATION.md). Внешнюю модель, физический телефон и официальную рубрику нельзя считать проверенными по одним имитациям API или статической вёрстке.

Ручной запуск на macOS/Linux (на этих ОС не проверен):

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
# Только если БД отсутствует:
.venv/bin/python backend/scripts/import_dataset.py
.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
# Во втором терминале:
cd frontend
npm ci
npm run dev -- --hostname 127.0.0.1 --port 3000
```

Стек сохранён: Next.js → FastAPI → SQLite, без нового агентного фреймворка. Архитектурный документ не менялся. Не реализованы корпоративный SSO, production-деплой, подключение документов/RAG, потоковый ответ, озвучивание и непрерывный голос. Статистика набора синтетическая; эффективность продукта и экономия бюджета требуют отдельной проверки.
