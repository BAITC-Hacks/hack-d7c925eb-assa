## Автоматические проверки

- `python -m unittest discover -s tests -v`: **2 теста, OK**.
- `npx tsc --noEmit`: без ошибок.
- `npm run build`: успешная production-сборка Next.js, страницы `/` и `/hr`.
- `git diff --check`: без ошибок пробелов.
- Проверка значения серверного ключа в JS-файлах клиентской production-сборки: совпадений нет; значение ключа не выводилось.
- Private: код сотрудника не даёт HR-роль и не меняет привязанный employee_id; чужой профиль/история и HR-инструменты недоступны; HR-сводка ограничена отделом.
- Импорт и изменяющие API-тесты выполнялись на отдельных временных БД. Основная БД не сбрасывалась и тестовые завершения в неё не добавлялись.

## Проверка браузером

Использован встроенный браузер Codex, не физический телефон.

- Desktop: открытие чата оставляет sidebar шириной 224 px; фокус переходит в поле ввода; до вопроса видны приглашение и команды, нет выданной за ответ рекомендации.
- 390×844: вопрос «Что делать дальше?» → проверенные карточки; «А второй вариант?» → объяснение Public Speaking Club; предыдущие карточки помечены и изменяющие действия отключены.
- 360×800: ширина документа 360 px, меню открывается и закрывается Escape, черновик «Черновик для проверки» сохраняется; фокус возвращается кнопке меню.
- 430×900: ширина документа 430 px; сравнение занимает одну колонку; карточки шириной 396 px укладываются в экран. Подтверждение завершения открывается с фокусом на «Ещё прохожу»; отмена не меняет данные.
- Смена сотрудник → HR очищает диалог. Запрос участия показывает 530 записей / 410 завершений (77,4%) для Backend Development на текущей основной БД; в отделе 40 сотрудников. После reload роль HR восстанавливается.
- Возврат к desktop оставляет рабочий чат и sidebar. Временный viewport override сброшен.

## Границы полной приёмки

1. **Реальная модель не вызывалась:** `CQ_ALLOW_EXTERNAL_AI` выключен. Проверены локальный путь, цикл инструментов на имитации и фактический таймаут. Для приёмки AI-качества нужен разрешённый доступ к модели, затем тот же набор свободных запросов и измерение общего времени ответа.
2. **Физический телефон, экранная клавиатура и микрофон не проверены.** Вёрстка проверена браузерным изменением viewport. Совместимость браузерного распознавания и допустимость его провайдера нужно подтвердить в целевом окружении.
3. Открытие чата отдельно от API измерено браузерным сценарием «нажатие → видимое поле»: 326 мс desktop и 297 мс при ширине 390 px (включая задержку управляющего инструмента). Эти два наблюдения укладываются в 2 секунды, но не заменяют нагрузочный тест и проверку физического телефона. SLA модели не подтверждён живым внешним вызовом.
4. Исходный конфликтный профиль и официальная рубрика из отсутствующего ТЗ не получены. Выполнены проверки на исходных 200 синтетических профилях и отдельных граничных фикстурах.
5. Чистый запуск проверен самим агентом на Windows, не независимым новым пользователем. macOS/Linux, HTTPS и сетевой доступ телефона не проверялись.
6. Сессии и контекст находятся в памяти одного backend-процесса. Токен/раздел восстанавливаются после reload, но визуальная лента и черновик — только при закрытии/открытии чата, не после reload. После рестарта backend требуется вход.
7. Добавочный импорт расширяет профили/историю в существующем каталоге; обновление оценок существующего профиля и расширение каталога требуют отдельного процесса. Потоковые ответы, SSO и production-деплой в этой итерации отложены планом.

Полная финальная приёмка не объявляется завершённой до закрытия перечисленных внешних условий.
